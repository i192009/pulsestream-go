# Observability

Prometheus scrapes each backend role every five seconds and Redpanda's public metrics. `pulse_events_total{stage,result}` counts acknowledgements, rejections, durable processing, duplicates, retries, outbox delivery, DLQ, alerts and replay. `pulse_duration_seconds{operation}` records publish, checkpoint, ClickHouse operations and backpressure waits. `pulse_resources{resource}` records fetched queue depth/capacity, worker capacity/activity, pending publication and WebSocket clients. Standard Go/process collectors expose CPU, resident memory, GC, goroutines and allocation activity.

Labels use fixed stages, rule kinds and resource names. Raw tenant IDs, users, account IDs, event IDs and unbounded rule IDs are not metric labels. Per-partition/checkpoint detail is available through the admin API. Live broker membership/lag is available through `/v1/groups`; `/v1/pipeline` records fetch-time lag and labels stale observations. The processor also samples live broker consumer lag every five seconds into pulse_resources{resource="consumer_lag"}. The dispatcher samples outbox depth/capacity. Measurements retain their last observed value during an outage rather than synthesizing zero progress.

OpenTelemetry propagates W3C trace context through raw Kafka headers. Partition-processing spans link to up to 32 input trace contexts per bounded batch; outbox rows carry traceparent metadata. Dispatch spans link to up to 32 originating contexts, and ClickHouse request spans are children of dispatch/query spans. This models asynchronous causality without pretending an entire stream is one synchronous request. The default parent-based root sample rate is 5%, with bounded exporter queues. The Compose collector exports to its debug logger; a searchable trace backend is not bundled. Configure an exporter to Tempo/Jaeger/your collector for trace search. Loss of telemetry does not roll back business state.

The provisioned Grafana dashboard shows broker acknowledgement throughput separately from durable processor progress, operation p95, queues/workers, retries/overload, memory, CPU, goroutines, DLQ/alerts and broker lag.
