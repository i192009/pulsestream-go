# Security and tenancy

All generated data is synthetic. No payment provider, personal financial record, production integration or regulatory-compliance claim is included.

Development API keys live in `PULSE_KEYS`; Compose sample credentials are deliberately local and public. Bindings use 127.0.0.1. Change credentials, configure TLS at ingress, restrict CORS/origins, and use a secret manager before exposing the services. No application API accepts a caller-specified SQL string. Tenant IDs always come from authenticated identities for analytical queries. Writer/admin keys may ingest only their own tenant. Reader keys cannot mutate rules, alerts or replay state. Redis uses a bounded noeviction policy so cache pressure cannot evict active quota counters; quota allocation failures reject new ingestion, while cache write failures merely bypass caching.

WebSocket tokens are sent in the first frame within five seconds; they are not put in URLs or access logs. Origins are compared exactly before upgrade. There are bounded read messages, connections, queues and write deadlines. The frontend uses sessionStorage scoped to the current tab, has a restrictive content security policy, and does not bundle API keys. It still requires protection against script injection; a stronger production deployment should use short-lived credentials and secure cookies or an identity proxy.

Health and metrics endpoints are intentionally unauthenticated infrastructure endpoints. Do not expose them publicly. Helm NetworkPolicy permits namespace-local application/dependency ports and DNS; review it against your CNI, ingress controller and monitoring namespace. Plaintext local Redis/Kafka/PostgreSQL traffic is isolated only by Docker networking. Application Kafka TLS/SASL client configuration and JWT/OIDC are **not** implemented; use a trusted development network and add tested transport/authentication support before production use. API keys are configuration-backed and require service rollout for rotation. mTLS between services is not configured.

Backend images run as UID 65532; dashboard Nginx runs unprivileged. Kubernetes backend pods use read-only root filesystems, dropped capabilities and RuntimeDefault seccomp. Dependency images have their own upstream security models. Full storage encryption, certificate rotation, backup restoration, multi-zone failover and compliance audits have not been demonstrated.

Logs use JSON and avoid payloads/credentials. DLQ envelopes intentionally retain original synthetic payload bytes; secure topic access and retention in any non-demo environment. The development Grafana permits anonymous viewer access on localhost and has a public sample admin password. Disable anonymous access and replace that password if changing network exposure.
